# Feedback Management System for AI & Manual Paths

## Objective

Implement a unified feedback system that allows users to provide feedback on completed paths while automatically routing the feedback to the appropriate owner based on how the path was created.

The system should support both:

- AI-generated Paths
- Partner-created (Manual) Paths

without creating separate feedback modules.

---

# Current Problem

Currently, users can generate or access different types of paths, but there is no ownership-based feedback routing.

Since two different entities create paths, feedback should not always go to the same administrator.

AI-generated paths belong to the Path Engine Team.

Manual paths belong to the respective Partner.

Therefore, feedback should automatically reach the correct owner.

---

# Goal

Create a centralized feedback module that:

- Allows users to rate and review paths.
- Automatically identifies who owns the path.
- Routes feedback to the correct dashboard.
- Allows Super Admin to monitor all feedback.
- Supports future AI learning and quality improvement.

# Technical Approach

## Step 1

Every published path must contain ownership information.

Example:

```json
{
    "path_source": "AI",
    "owner_id": "path_engine_admin"
}
```

or

```json
{
    "path_source": "PARTNER",
    "owner_id": "partner_123"
}
```

These two fields become the key for routing feedback.

---

## Step 2

User submits feedback.

Example:

```text
★★★★★

Rating

Comments

Submit
```

---

## Step 3

Backend automatically identifies

- Path Source
- Owner

and stores feedback.

No frontend routing logic is required.

# Final Outcome

The platform will have one centralized feedback system capable of handling both AI-generated and manually created paths.

Users submit feedback only once.

The backend automatically routes feedback based on the path owner.

- AI Path → Path Engine Admin + Super Admin
- Manual Path → Partner + Super Admin

This approach keeps the implementation simple, scalable, maintainable, and aligned with the existing Naaviverse architecture.
